# शाश्वत — Cinematic AI OS Interface: Implementation Plan

## Mission (per your spec)
Turn the existing 4-state voice assistant into a *living digital intelligence*: a real-time deforming 3D orb with volumetric bloom, an atmosphere that transforms across **13 AI states**, Maheshwar-sutra holographic orbiters, a cinematic living background, a refined glass dock, spring microinteractions, and GPU-accelerated but *adaptive* performance. Not a redesign — a depth and life upgrade on the existing layout.

## Verified constraints that shape every decision
- **Three.js postprocessing is already in `node_modules`** (`EffectComposer`, `RenderPass`, `UnrealBloomPass`, `OutputPass`) and **fully typed** by `@types/three@0.185.1`. Import as `three/examples/jsm/postprocessing/X.js`. **No new dependencies.**
- **`@/` = repo root** (so `@/src/...`). TS is **non-strict**; `isolatedModules` is ON → type-only imports use `import type`.
- `npm run build` uses esbuild (no type-check); `npm run lint` (`tsc --noEmit`) is the type gate. I'll keep it green.
- **`<StrictMode>` is ON** → all WebGL `useEffect`s must be idempotent (mount/cleanup), with `forceContextLoss()` to avoid dev leaks.
- **State today is 100% client-inferred; the server emits no thinking/executing signal.** Two clean server injection points confirmed: `server.ts:616` (toolCall arrived) and `server.ts:642` (`await executeTool`). No system-prompt or tool-declaration changes needed.

## Critical performance fix (foundational — fixes a real bug)
`AssistantOrb.tsx:364` has `useEffect(..., [state, volume])`. Since `volume` changes ~every frame during audio, the **entire WebGL scene is torn down & rebuilt dozens of times/sec** (geometry, shaders, 14 sutra textures, context). This is the #1 perf problem and undermines the whole spec. **Fix:** mount-once pattern with a mutable ref read each frame. Same hardening for `BackgroundCanvas`. This alone will make the existing UI dramatically smoother and is a prerequisite for adding heavier effects.

## Phase 1 — Type system & 13-State architecture (the backbone)

**`src/types.ts`** — expand the union and add a theme descriptor consumed everywhere:
```ts
export type AssistantState =
  | 'booting' | 'idle' | 'wakeWord' | 'listening' | 'understanding'
  | 'reasoning' | 'searching' | 'executing' | 'speaking' | 'learning'
  | 'success' | 'error' | 'sleeping' | 'disconnected';
// (keep 'disconnected' so legacy code keeps working; map it onto 'sleeping' visually)
```
- **`src/theme/aiState.ts`** (NEW): the single source of truth for the *atmosphere per state* — a `STATE_THEME: Record<AssistantState, StateTheme>` map. Each entry defines: `baseColor`, `accentColor`, `fresnelColor`, `bloomColor`, `orbSpeed`, `orbAmp` (deformation intensity), `orbBreath` (breathing rate), `particleSpeed`, `particleBrightness`, `sutraSpeed`, `sutraOpacity`, `hudAccent`, `motionIntensity` (0–1, drives background + global easing). **Every visual layer reads from this map**, so a state change transforms the whole app in one place — exactly the spec's "each state should affect orb / particles / lighting / background / HUD / accent colors / motion intensity."

**`src/state/useStateMachine.ts`** (NEW hook): holds the live `AssistantState`, exposes `setState`, and runs the **derivation rules**:
- `booting` → app launch (timed ~1.8s intro) → `idle`.
- WS audio arrives → `speaking`; interrupted/barged → `listening`.
- user-input-detected (volume rise) → `listening`.
- **New server `phase` signals** → `reasoning` / `executing` / `searching` / `understanding`.
- tool success/fail → `success` / `error` (auto-return to listening after 1.5s).
- idle-timeout (e.g. 30s no activity) → `sleeping`; wake-word → `wakeWord` → connect.
- Added safety: a client-side **"reasoning" heuristic fallback** — if user stops speaking and no audio arrives within ~700ms, show `understanding` then `reasoning` until first audio/turnComplete. This keeps the experience alive even before/without server signals.

**Legacy compatibility:** `LiveSession.ts` already calls `onStateChange(new)`. I map its existing `'connecting'`→`booting`/`reasoning`, and route new server `phase` messages through the same hook. No churn in feature modules.

## Phase 2 — Server state signaling (the "Full" option you chose)

Add ~3 lightweight WS signals at the verified injection points in **`server.ts`** (no prompt/declaration changes):
1. **On toolCall arrival (line ~616):** `clientWs.send({ type:'phase', phase:'reasoning' })` → then `'executing'` as `executeTool` is entered (line ~642). For known search/browser tools (`browser_navigate`, `live_search`, `browser_sandbox_exec`), emit `'searching'`.
2. **Before first audio chunk of a turn:** emit `'understanding'` once per turn (tracked via a per-connection flag reset on `turnComplete`/`interrupted`), so the silent gap between user-speech-end and first audio is no longer blank.
3. **`turnComplete`:** the hook auto-returns to `listening`/`idle`.

**`src/modules/LiveSession.ts`** gains a `onPhase(phase)` handler wired into `useStateMachine`, and a `setPhase` passthrough so the sandbox/learning panels can also drive atmosphere (`learning`).

These changes are additive and backward-compatible — if a client doesn't handle `phase`, nothing breaks.

## Phase 3 — The Living Orb (modular rebuild in `src/components/orb/`)

The empty `orb/` dir becomes a focused, tunable engine. **`AssistantOrb.tsx` becomes a thin mount-once shell** that renders `<OrbScene>`.

New modules under `src/components/orb/`:
- **`shaders.ts`** — the GLSL library, refactored & upgraded from the current monolithic inline shader:
  - 3D simplex noise (kept) + a **second lower-frequency noise octave** for layered, non-looping "fluid deformation."
  - **Fractional Brownian motion** displacement so the surface flows organically (procedural, never repeating).
  - Enhanced **fresnel** rim lighting + **perceptual-brightness** color mixing.
  - An **energy-circulation** swirl term in the fragment shader (inner convection currents).
- **`OrbScene.tsx`** — the orchestrator. Mounts **once** (`useEffect([])`), reads `stateThemeRef` + `volumeRef` each frame (the perf fix). Composes the layers below and owns the `EffectComposer`.
- **`PlasmaCore.ts`** — the deforming blob (Icosahedron high-subdivision) with the upgraded shader; **layered** (outer membrane + inner brighter plasma sphere) for volumetric depth; breathing via sin on base radius scaled by `orbBreath`.
- **`EnergyParticles.ts`** — a **dynamic particle ecosystem** orbiting the core (GPU points, additive blend): particles spawn at the surface, spiral inward then outward (inner energy circulation), velocity/brightness driven by `motionIntensity` + audio. Voice-reactive scale pulse.
- **`HaloField.ts`** — soft additive sprite halos + a faint refraction-style distortion shell for the "volumetric glow / refraction / reflection" look without a full env-map cost.
- **`SutraOrbiters.ts`** — the 14 Maheshwar Sutras as holographic streams. Upgraded from static ring to **drifting wave paths** (Lissajous-style orbits at varied radii/inclinations), low opacity, gentle fade in/out (sin envelopes), and **react during listening/reasoning** (opacity + speed step up). Spiritual + futuristic, not decorative.
- **`postprocessing.ts`** — `EffectComposer` → `RenderPass` → `UnrealBloomPass` → `OutputPass`. Bloom params (`strength`, `radius`, `threshold`) sourced from `STATE_THEME.bloomColor` & motion intensity (e.g. `success` flares brighter, `sleeping` dims). **Gated by quality tier** (see Phase 7) — at Low quality, composer is skipped and `renderer.render` is used directly.
- **`interaction.ts`** — mouse spring-follow + tilt + **click ripple** that radiates a displacement wave through the blob (ripples originate from interaction points). Voice-reactive movement reads `volumeRef`.
- **`useOrbQuality.ts`** — picks the subdivision/particle-count/bloom tier from the global quality system.

**Mouse + voice reactivity, breathing, procedural (non-looping) motion, state-dependent colors** are all driven by the `STATE_THEME` ref → the orb literally *is* the AI's state.

## Phase 7 — Performance: adaptive quality & reduced-motion (spec: "gracefully reduce on lower-end systems")

**`src/perf/useRenderQuality.ts`** (NEW) — a single adaptive-quality engine:
- **Tier detection on mount:** High / Medium / Low from `navigator.hardwareConcurrency`, `devicePixelRatio`, GPU vendor, and an **initial micro-benchmark** (render ~30 frames, measure avg FPS).
- **Runtime FPS watchdog:** a rolling FPS sample across both WebGL loops; if FPS < 45 for ~1.5s, **auto-degrade** one tier (drop bloom, halve particles, lower subdivision). If FPS recovers >58 for a while, cautiously step up.
- **Quality → effects mapping:** High = bloom + full particles + full subdivision + noise; Medium = bloom + reduced particles; Low = no composer, few particles, low subdivision, no noise.
- **`prefers-reduced-motion`:** force Low tier, disable parallax/noise, freeze breathing to a near-static idle — still beautiful, never seizure-inducing.
- Exposes a global `qualityRef` that `OrbScene`, `BackgroundCanvas`, and particle counts read each frame (no re-mount to change tier).
- **GPU-acceleration hygiene:** `powerPreference:'high-performance'` on renderers, `antialias` only on High/Medium, capped DPR, `forceContextLoss()` in cleanups (StrictMode-safe).

**Perf targets:** High-tier 60fps on modern discrete GPUs; graceful 30–60fps Medium on integrated graphics; never a slideshow on Low.

## Risks & mitigations
- **StrictMode double-mount WebGL** → idempotent effects + `forceContextLoss()` (verified pattern).
- **Bloom cost on weak GPUs** → adaptive tiers + FPS watchdog auto-degrade (Phase 7).
- **State-derivation flicker** → debounced transitions + "reasoning" heuristic fallback so the atmosphere is always deliberate, never jittery.
- **Server `phase` is additive** → old clients ignore unknown `type:'phase'`; fully backward-compatible.

This delivers, in one cohesive pass, every area you prioritized: the **Living Orb**, the **13-state atmosphere system** (client + server), **cinematic background + Maheshwar sutras**, and **dock/microinteractions/reduced-motion/adaptive performance**.
